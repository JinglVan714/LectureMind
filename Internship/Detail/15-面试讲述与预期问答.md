## 一、怎么介绍这个项目

### 1.1 一句话（10 秒）

> 从 B 站视频自动生成结构化讲义 + 可问答知识库的系统，核心链路是「视频采集 → VLM 视觉理解 → 多 Agent 协作提取 → 双投影编译 → RAG + Copilot 对话」，并通过 MCP 协议暴露给外部 Agent。

### 1.2 电梯演讲（30 秒）

输入一个 B 站链接，自动完成字幕提取、关键帧采样、VLM 视觉理解，然后通过多 Agent 协作（StudyQuestion / Critic / Reviser）生成结构化 LectureIR，再编译成「人类可读讲义 HTML」和「机器可读证据索引」两份产物。最后向量化 + 全文索引，接 LangGraph ReAct Agent 做 Copilot 问答，通过 MCP 暴露给 Cursor / Claude Desktop。

### 1.3 完整介绍（3-5 分钟）

**(1) 动机（30 秒）**：视频学习无法搜索、跳转、定位知识点。目标是把视频变成可检索、可问答的结构化知识资产。

**(2) 架构（1 分钟）**，5 层：

```
接入层：FastAPI Web UI + Copilot SSE + MCP Server（stdio / HTTP+SSE）
编排层：Pipeline 8 阶段（metadata → ingest → VLM → profile → IR build → render → persist → RAG）
理解层：VLM 分级 + 长度路由 + ChapterPlanner + 多 Agent + Map-Reduce
存储层：3 个 SQLite 文件分离（主库 / VLM 缓存 / 章节缓存）
模型层：DeepSeek V4（文本+Copilot）+ Qwen VL（视觉）+ DashScope Embedding
```

**(3) 3 个技术亮点（1.5 分钟）**：

- **长度感知路由**：4 档 profile（tiny/standard/long/epic），每档不同章节策略、IR 构建方式（单次 vs Map-Reduce）、Critic 粒度、Reviser 模式。10 分钟视频和 2 小时视频走完全不同路径。
- **双投影编译**：同一份 LectureIR → LectureNoteIR（人类阅读）+ EvidenceIndex（系统消费），渲染和检索共享结构化数据。
- **多 Agent + 白名单补丁**：StudyQuestion 引导 → Critic 审查 → Reviser 用 IRPatch 白名单（只允许改 5 类字段，禁改章节/时间戳）定向修正，schema 校验失败整批回滚。

**(4) 工程化（30 秒）**：25 个测试文件、280+ 用例、13+ 真机回归脚本、preflight 自动安全检查、Docker 一键部署。

### 1.4 不同岗位侧重点

| 岗位 | 重点讲 | 少讲 |
|------|--------|------|
| 后端/全栈 | Pipeline 编排、双投影、Storage、Config 降级 | VLM 细节 |
| AI/Agent | 多 Agent 协作、白名单、Map-Reduce、RAG | Docker |
| MCP/基础设施 | MCP 双 transport、独立进程、summarize 隐藏 | 前端 |
| 工程化/质量 | 测试矩阵、真机回归、preflight、降级矩阵 | VLM 算法 |

## 二、核心叙事（面试官能记住的 3 点）

1. **不是调一个 API**：8 阶段、3 个模型、多轮 Agent 协作，每步有降级。
2. **一份数据两种消费**：LectureIR → 人类讲义 + 机器证据索引。
3. **默认安全，显式放开**：summarize 默认隐藏、Reviser 默认关、strict 默认关。

## 三、预期问题与回答

### 架构设计

**Q1: 为什么不用 LangChain 自己写 Agent 协作？**

LangChain AgentExecutor 对多角色 DAG（StudyQuestion → IR → Critic → Reviser）支持弱。Critic-Reviser 间有严格数据契约（CritiqueIssue → IRPatch），LangChain output parser 不够表达。Copilot 的 ReAct 场景用了 LangGraph——选型按场景，不站队。

**Q2: 为什么用 SQLite 而非 PostgreSQL？**

部署目标本地自托管，零外部依赖。sqlite-vec + FTS5 原生扩展够用。3 个 SQLite 文件物理分离让缓存生命周期独立。未来规模化 RAG 层可换 pgvector，主库不动。

**Q3: 双投影编译的设计动机？**

渲染需要「代码属于哪个教学单元、旁边放哪张帧」→ LectureNoteIR。检索需要「文本证据来源、关联知识点、锚点秒数」→ EvidenceIndex。混在一起互相污染。分开编译后改模板不影响检索，改 chunking 不影响排版。共享 LectureIR 源保证一致性。

**Q4: ChapterPlanner 为什么用确定性规则而非 LLM？**

成本：每次 pipeline 省一次 API 调用。确定性：同一视频两次必须切相同章节，否则 chapter cache 全 miss。三信号互补：transition phrase（0.85）→ silence（0.6）→ visual shift（0.55），取并集 snap 到字幕边界，max_chapter_duration（720s）兜底。

---

### Agent / LLM

**Q5: Critic 和 Reviser 为什么分开？**

职责不同（找问题 vs 修问题），合在一起 LLM 容易「为修而找」或「找了修错」。审查粒度不同（full vs projected）。安全边界不同：Reviser 有 IRPatch 白名单限制修改范围，Critic 没有。

**Q6: IRPatch 白名单怎么工作？**

`_OP_PATTERNS` 定义 5 个合法操作的正则。LLM 输出的 patch 过白名单——path 不在表直接 reject。`apply_patches` 逐 patch 应用，rejected 不中断 batch。最后 `LectureIR.model_validate` 校验——失败则整批回滚，追加 `RejectedPatch(patch=None, reason='schema_violation')`。保证「Reviser 只能让 IR 变好，不能变非法」。

**Q7: Map-Reduce 的 reduce-global 为什么 fail-fast？**

reduce-global 生成 mainline 和 knowledge_units——全局结构。失败意味着全局理解丢失，降级产出会误导用户。map 单章失败可放占位符（其他章节完整），但 reduce-global 不行。所以重试耗尽抛 `ReduceGlobalError`，走 v1 fallback。

**Q8: token 成本怎么控制？**

VLM 分级（HIGH/LOW 两档 prompt，省 ~40% token）+ VLM 缓存（SHA256 内容寻址跨视频复用）+ Critic projected mode（长视频只看 IR 摘要，prompt 从 ~50K→~15K chars）+ Reviser 只给被引用章节 + Chapter cache（prompt_hash 寻址）。

---

### 工程化

**Q9: 怎么处理各种失败？**

24+ 处降级分三类：核心路径 fail-fast（metadata/ingest/IR/render/persist）；增强路径降级（ChapterPlanner→空 plan、ChapterCache→noop、Critic/Reviser→不修正、RAG→warning）；自动 fallback（单次 IR 截断→Map-Reduce、v2 全失败→v1）。`LECTURE_STRICT_AGENTS` 控制开发态 vs 生产态。

**Q10: 怎么保证两次处理结果一致？**

ChapterPlanner 确定性规则 → 章节可复现。ChapterCache prompt_hash（SHA-256 of segments+frames+boundaries+model+version）→ 同输入必命中。VLM 缓存 image_sha256 → 同帧必命中。Keyframe timestamp 量化到 ms（commit 09df83f）→ fresh vs cached 路径 hash 一致。唯一不可复现的是 LLM 输出本身——但缓存让同输入只调一次。

**Q11: embedding 维度变化为什么抛异常？**

向量维度变 = 语义空间变，新旧向量混检结果完全错误。自动迁移成本极高不可中断。设计上抛 `EmbeddingError`，要求手动 `reindex --reset-vectors`，让操作可感知可回滚。

### MCP / API

**Q12: MCP server 为什么独立进程？**

协议不同（JSON-RPC vs REST）、生命周期不同（IDE spawn 子进程 vs 常驻服务）、权限模型不同（token vs Basic Auth）。共享业务逻辑（`tools.py`），不共享进程。

**Q13: summarize_video 为什么默认隐藏？**

唯一写操作 + 重 IO + 高成本工具。默认暴露会被外部 Agent 误调用。设计哲学：「读默认开，写默认关」。显式设 `MCP_EXPOSE_SUMMARIZE=true` 才注册。

**Q14: 为什么选 SSE 而非 WebSocket？**

Copilot 交互是单向流（server→client），不需双向。SSE 基于 HTTP，代理/CDN 兼容好，浏览器原生支持。5 种 event 类型：token / tool_call / tool_result / error / done。

### 决策与取舍

**Q15: 最大技术挑战？**

长视频 token 预算管理：2 小时课程字幕 ~5 万字 + 关键帧 ~80 张 + VLM ~2 万字。三层压缩：VLM 分级（帧层面）→ ChapterPlanner 切分（时间层面）→ Map-Reduce（空间层面），每层保证质量前提下削减 token。

**Q16: 如果重做会改什么？**

ChapterPlanner visual shift 用 CLIP embedding 替代 VLM 描述 diff（准确率 55%→70%+）。双投影改增量编译（只重编 Reviser 修改过的章节）。MCP summarize 改配额制（每月 N 次）替代二态开关。

**Q17: 为什么选 DeepSeek 而非 GPT-4？**

成本 ~1/10、128K 上下文、function calling 够用。模型选择配置化（`DEEPSEEK_BASE_URL` 可指向任何 OpenAI 兼容 endpoint）。

**Q18: 项目局限性？**

只支持 B 站（YouTube 需改 ingest 层，但架构支持）。Whisper 中文专业术语偶有错误，无术语纠错。Copilot ReAct 限 6 步，复杂问题需多轮。无用户反馈闭环。

---

### 刁钻追问

**Q19: Critic 怎么保证比 IR builder 聪明？如果 Critic 也犯错？**

Critic 价值在视角不同（提取 vs 审查），不是更聪明。防御：Critic 只建议不直接改；IRPatch 白名单限制落地范围；schema 校验最后防线；`LECTURE_CRITIC_ENABLED=false` 可完全关闭。

**Q20: RAG 检索质量怎么评估？**

间接评估——真机回归验证 Copilot 锚点有效性。没做系统性消融实验（工程交付项目非研究项目）。要补可用 Ragas 跑 faithfulness + context precision + context recall。

**Q21: 没字幕怎么办？Whisper 够吗？**

CC 优先 → Whisper 兜底。Whisper base 中文 WER ~10-15%，理解语义够，精确引用不够。`mark_unverified_points` 用 fuzzywuzzy 模糊匹配验证 quote，找不到打 ⚠️。精度要求高可换 `WHISPER_MODEL=large-v3`。

## 四、不要做的事

- 不要背架构图——用「视频进来→经过什么→变成什么」叙事。
- 不要列技术栈——说「为什么选」而非「用了什么」。

- 不要把 Agent 讲成「调了几个 API」——强调数据契约、安全边界、失败回滚。
