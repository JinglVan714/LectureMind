## 一句话定位

LectureMind 是一个把 Bilibili 长视频编译为「可阅读讲义 + 可追溯证据 + 可问答 Copilot + 可对外 MCP」的本地化 Agent 应用，整套链路围绕一个结构化中间表示 `LectureIR` 展开。

## 五层架构

整个系统可以稳定地拆成 5 层，每一层的职责、入口模块和数据形态都不重叠：

| 层 | 目录 | 核心入口 | 输入 | 输出 |
|----|------|---------|------|------|
| **1. 原料采集** | `app/ingest/` | `BilibiliIngest` / `SubtitleExtractor` / `KeyframeExtractor` / `CoverCache` | URL 或 BV 号 | `VideoMeta` / `SubtitleSegment[]` / `Keyframe[]` / 封面文件 |
| **2. 视觉理解** | `app/understand/vlm.py` | `FrameDescriber` | `Keyframe[]` | `FrameDescription[]`（caption / ocr / 评分） |
| **3. 结构化理解** | `app/understand/` | `LectureIRBuilder` + Agents + `MapReduceIRBuilder` | `LecturizeContext` | `LectureIR` |
| **4. 编译与渲染** | `app/understand/lecture_compiler.py` + `app/render/` | `compile_lecture` + `Renderer` | `LectureIR` | `LectureJSON`（含双投影） + HTML |
| **5. 消费层** | `app/copilot/` + `app/copilot/mcp_server.py` | `/api/copilot/*` + `FastMCP` | 问题 / 工具调用 | SSE 流 / 工具返回 |

中间还有一层基础设施：`app/storage/db.py`（SQLite）、`app/copilot/rag.py`（向量 + FTS）、`app/config.py`（统一配置）。

- **`profile`** — `select_profile(meta.duration, settings)` 选择 `tiny / standard / long / epic` 四档（`@d:\Diet_Agent_NEW\app\pipeline.py:171-182`）。
- **`chapter_plan`** — `plan_chapters(...)` 推断章节锚点；失败降级为空（`@d:\Diet_Agent_NEW\app\pipeline.py:188-217`）。

- **`lecture_ir`** — `LectureIRBuilder.build_with_agents(...)` 或回退到 v1（`@d:\Diet_Agent_NEW\app\pipeline.py:227-283`）。

整个链路的 telemetry 都挂在 `Pipeline.last_run_timing` 和 `last_run_stats` 上，验证脚本（`scripts/_verify_lecture_v2_real_e2e.py`）会把它落成 `data/debug/<BV>.timing.json`。

## 模型栈：text / vision / embedding 分栈

模型分配的事实写在 `@d:\Diet_Agent_NEW\app\config.py:24-83`：

- **文本与 Copilot** — DeepSeek 官方 API（OpenAI 兼容协议）。
  - 配置项：`DEEPSEEK_API_KEY` / `DEEPSEEK_BASE_URL`。
  - 默认模型：`deepseek-v4-flash`（实际通过 alias 复用 `QWEN_TEXT_MODEL` 字段）。
- **视觉（VLM）** — DashScope Qwen 多模态。
  - 配置项：`DASHSCOPE_API_KEY` / `QWEN_VL_MODEL`。
  - 默认模型：`qwen3.5-omni-plus`。
- **Embedding** — DashScope `MultiModalEmbedding`（同一密钥）。
  - 默认模型：`qwen_embedding_model` 设置项。

这个分栈的工程含义在 `config.py` 的注释里说得非常直白：**用 DeepSeek V4 的价格优势压文本成本，同时保留 Qwen 在视觉 + 多模态 embedding 上的质量**。

## 关键中间表示一览

LectureMind 的关键设计是「不把 HTML 当事实源」。从一段视频到最终消费层，会经过 4 个结构化中间表示，每一层都可独立持久化和重渲染：

| 表示 | 模块 | 形态 | 服务于 |
|------|------|------|--------|
| **`LectureIR`** | `app/understand/ir.py` | Pydantic 模型，含 profile/chapters/knowledge_units/visual_evidence | 编译输入 |
| **`LectureJSON`** | `app/understand/schema.py` | 投影后的「合法对外结构」，附带 blueprint / note_ir / evidence_index / composition | 渲染、入库、RAG |
| **`LectureNoteIR`** | `app/understand/schema.py::LectureNoteIR` | 面向读者的教学单元结构 | HTML 渲染、Copilot note-first 检索 |
| **`EvidenceIndex`** | `app/understand/schema.py::EvidenceIndex` | 面向系统的证据对象 + 关系 + 锚点 | Copilot evidence-second 检索、MCP |

这四层结构存在于一份 `summaries.summary_json` 中，所以一次生成可以养活：HTML 报告、RAG 索引、Copilot 工具调用、MCP 对外接口。

## 双 SQLite 缓存

除主库 `data/app.db` 外，系统还有两个独立 SQLite 文件，各自承担一种缓存任务：

- **`data/vlm_cache.sqlite`** — 由 `app/understand/vlm_cache.py::VLMCache` 维护，键为 `(sha256(image_bytes), model, tier)`。同一张幻灯片跨视频也能命中。
- **`data/chapter_cache.sqlite`** — 由 `app/understand/chapter_cache.py::ChapterCache` 维护，键为 `compute_prompt_hash(chapter)`。长视频 Map-Reduce 中**每一章一行**，重跑同一 BV 时整章命中。

这两个缓存与主库分离的原因是显而易见的：它们是「内容寻址」缓存，跟 `summaries` / `assets` 的「实体寻址」语义不同。把它们物理隔离能让数据库迁移和清理更简单。

## 长视频路由：profile / chapter / map-reduce / cache

长视频处理是项目最不像「prompt demo」的部分。完整路径如下：

- `app/understand/profile.py::select_profile(duration_sec, settings)` — 按 `(180, 900, 3600)` 秒阈值分到 `tiny / standard / long / epic`。
- `tiny / standard` — 走单次 `LectureIRBuilder.build_with_agents`，Critic full / Reviser patch。
- `long / epic` — 走 `MapReduceIRBuilder`：每章一个 map LLM 调用，pure-Python local reduce，一次轻量 global pass。Critic 用 projected 模式，Reviser patch。

详见 `@d:\Diet_Agent_NEW\app\understand\profile.py:71-118` 的策略表。
